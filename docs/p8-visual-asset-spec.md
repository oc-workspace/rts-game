# P8 舰船视觉资产规格

## 1. 目的与范围

P8 的目标是把当前可玩的程序化舰船原型，逐步升级为具有统一工业硬科幻语言、可替换资产接口和明确性能预算的舰队视觉。第一轮先验证 scout 的近景层级和资产契约，再把同一套规则推广到 striker、carrier 和环境资产。

本阶段不承诺一次性达到最终商业 AAA 资产质量，也不以增加发光、零件数量或面数作为完成标准。所有视觉改动必须保留当前的选择、移动、战斗、远景 LOD、实例化和低特效降级路径。

## 2. 三类舰船视觉职责

| 舰种 | 视觉关键词 | 轮廓职责 | 近景识别细节 | 远景识别细节 |
| --- | --- | --- | --- | --- |
| scout | 轻、快、侦察、传感器 | 尖锐窄体、外伸翼、前置传感器 | 传感器舱、背脊、散热片、编号贴花 | 窄长尖首、双侧翼、青蓝/琥珀识别色 |
| striker | 武装、压制、火力 | 宽肩、前装甲、双侧炮位 | 炮塔、炮管、装甲拼接、武器挂点 | 宽体、双炮位、醒目的前向火力轮廓 |
| carrier | 厚重、指挥、投送 | 大体量、双侧机库、中央指挥塔 | 机库门、指挥舱、天线、分段装甲 | 巨型体量、双侧机库、中央高塔 |

## 3. 资产层级契约

每个舰船视觉由以下层级组成，层级名称对应 `ShipView` 与 `src/render/ship-visuals.ts` 的运行时职责：

```text
ShipView.group
├── detailGroup                 # 近景完整视觉，可替换正式模型
│   ├── primary hull             # 主舰体轮廓与材质
│   ├── functional modules       # 传感器、炮位、机库、指挥舱
│   ├── surface language         # 装甲板、背脊、散热片、贴花
│   ├── damage overlays          # 生命值驱动的损伤层
│   └── thrusters                # 高/低特效共同保留的推进核心
├── distantHull                  # 单舰远景 LOD
└── selectionRing + shipLight    # 选择反馈与高特效局部光源
```

正式资产接入时必须提供：

- 统一朝向：舰首为 `+Z`，底部贴近 `SHIP_Y`，模型原点位于舰体质量中心；
- 三档视觉策略：近景 detail、远景简化 hull、压力场景 instanced batch；
- 可选模块挂点：推进器、武器、传感器、损伤和阵营贴花；
- 不依赖 DOM 或 renderer 状态的单位 ID 映射；
- 资产来源、授权、文件格式、尺寸、贴图分辨率、三角面预算和回退资产记录。

## 4. 材质与颜色预算

- 主舰体使用低饱和深色金属，阵营色只用于识别条、传感器、推进器、武器和选择标记；
- 近景默认最多使用主舰体、装甲、功能模块、面板/玻璃、阵营发光五类材质；
- 不为单个小零件创建独立材质，优先共享 `MaterialSet` 或合并纹理；
- 高特效允许局部 emissive、点光源和命中闪光，低特效必须保留轮廓、推进核心、选择环和武器轨迹；
- 贴花和损伤层必须使用 polygon offset 或明确的深度策略，避免 z-fighting。

## 5. 性能预算

P8 第一轮以当前 200 单位压力结果为回退基线：

| 项目 | 近景单舰目标 | 远景/压力目标 |
| --- | ---: | ---: |
| detailGroup 子网格 | scout ≤ 24，striker ≤ 32，carrier ≤ 42 | 不参与远景批次 |
| 远景批次 | 不适用 | 阵营 × 舰种最多 6 批 |
| 额外动态点光源 | 每舰最多 1 个，压力场景按距离限制 | 压力场景继续保持最多 12 个 |
| 战斗表现 | 复用现有对象池 | 总池上限 256 个 GPU 对象 |
| 贴图 | 优先共享 128/256 级纹理图集 | 实例化路径不增加贴图采样种类 |

任何正式资产若超出预算，必须同时提交 profiling 数据、低成本替代方案和回退开关，不能直接扩大默认上限。

## 6. P8 第一轮验收

- 固定 seed `20260810` 下，三类舰船仍可凭轮廓和阵营识别；
- scout 第一轮视觉升级至少包含主舰体、传感器、功能模块、装甲/散热层和推进器层级；
- 单选、框选、移动、攻击、损伤、选择环、远景 LOD 和 200 单位实例化拾取不回退；
- 高/低特效切换不改变 simulation 结果；
- 1280×720 和 390×844 页面无 HUD 遮挡、溢出或新控制台错误；
- 进度日志记录实际截图/浏览器结果、性能变化和未完成的资产工作。

## 7. P8 第二轮材质与损伤验收

- 不通过增加子网格堆叠细节，scout、striker、carrier 继续保持 24、32、39 个 `detailGroup` 直接子网格；
- 主舰体、装甲、功能面板和不透明玻璃使用独立但共享的 128×128 程序化表面/粗糙度纹理，避免透明排序回退；
- 三舰种使用各自的舰种代码、职责文字和轮廓图标贴花，仍只占用现有单张 registry plane；
- 三阶段损伤使用不同的烧蚀、裂纹和结构破口纹理，并按舰种设置位置，不新增损伤 plane 数量；
- 低特效关闭高成本损伤覆盖时仍保留舰体轮廓、阵营色、推进核心、选择环和武器轨迹；
- 固定 seed 的桌面、手机、实战和 200 单位实例拾取均无规则、布局、LOD 或控制台回退；
- 新视觉基线必须来自本轮实际构建；截图工具不可用时保留既有基线并在进度日志明确记录，不得用旧图冒充新结果。

## 8. P8 第三轮 scout 正式资产试点

第三轮先只替换 scout 的近景主舰体、装甲、翼面和功能面板，传感器、阵营识别、registry、损伤层、推进器、选择环和远景路径继续由现有运行时模块负责。

- 正式模型使用 glTF 2.0，舰首保持 `+Z`、`+Y` 向上、原点位于近似质量中心；模型由 5 个语义网格、124 个三角面组成。
- 主舰体使用 512×512 base color 与 roughness 位图；位图只承担中性硬表面语言，阵营颜色继续由共享材质 tint 控制。
- `public/assets/ships/scout/v1/asset-manifest.json` 必须记录模型与贴图来源、权利说明、尺寸、哈希、性能预算和回退路径。
- glTF loader 使用异步分包；资源全部加载成功后才原子替换程序化核心，任一模型、buffer 或贴图失败时必须继续显示现有程序化 scout。
- 固定 seed URL 可追加 `scoutAsset=fallback` 强制使用程序化近景资产，用于正式资产与回退路径的确定性对照；该参数不得改变 simulation、单位 ID、LOD 或实例映射。
- 正式资源启用后，scout 近景保持不超过 24 个渲染网格；远景 hull 与 200 单位实例批次不加载 glTF 或新增贴图采样种类。
- 第三轮视觉验收使用 `inspectUnit=<id>` 或无选中框的 `captureUnit=<id>` 建立确定性镜头；`pixelRatio=1` 只用于降低 QA 捕获成本，`captureFrame=1` 只在显式启用时打开 `preserveDrawingBuffer` 并导出一次画布帧，默认游戏路径不改变 WebGL buffer 策略。
- scout base color 源图自身已包含 2×2 宏观面板，因此运行时 UV repeat 固定为 1×1；正式资源加载完成后允许对共享阵营 tint 做仅限 scout 外部资产的明度补偿，程序化回退与其他舰种材质保持不变。
- 1280×720 正式/回退近景与 390×844 正式移动端基线均通过后，scout 资产契约可推广到 striker；推广的是 glTF、manifest、原子替换、回退开关和 QA 捕获契约，不复制 scout 的轮廓或材质数值。
