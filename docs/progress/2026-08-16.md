## Completed

### Carrier model and PBR assets

- 新增 `public/assets/ships/carrier/v1/`：10 个语义网格、252 个三角面的 `carrier-v1.gltf`/`carrier-v1.bin`，512×512 base color/roughness、最终生成 prompt 和 `asset-manifest.json` 均纳入仓库。
- 模型保持 `+Z` 舰首、`+Y` 向上，尺寸为宽 19.68、高 5.45、长 25.15；长纵深主舰体、指挥脊、舰首/舰尾甲板、双侧机库、舱门、发射眉、外轨和功能面形成航母级体量。
- base color 使用内置 OpenAI imagegen 生成无文字、中性、低频的长条甲板和机库维护面，没有提供第三方参考图；roughness 从缩放后的 512×512 底色确定性灰度和范围压缩派生，最终 prompt 随资源提交。
- `scripts/build-carrier-model.mjs` 与 `npm run assets:carrier` 可重复生成相同 10 网格、252 三角面和模型哈希。

### Runtime contract and fallback

- 新增异步 `carrier-asset.ts`：glTF、binary、base color 和 roughness 全部成功后才原子移除 16 个程序化核心网格，任一失败继续保留 fallback。
- `carrierAsset=fallback` 可强制程序化近景，不改变 seed、simulation、单位 ID、LOD 或实例映射。
- 指挥甲板/塔、桥灯、传感器、着舰引导、阵营条、registry、damage、三组 thrusters、selection ring、远景 LOD 和实例批次继续使用既有运行时路径。
- 正式 Carrier 共 33 个近景渲染网格，低于 42 预算；程序化核心 16 个网格被 10 个 glTF 网格替换。
- Carrier QA 捕获缩放从通用 0.28 调整为按舰种 0.36，确保 390×844 能保留舰首、指挥塔和双侧机库；Scout/Striker 捕获仍为 0.28，正常游戏摄像机不变。

### P8 第四轮环境视觉基线

- 新增 `src/render/environment-visuals.ts` 与对应 Vitest 契约测试，统一背景、小行星、目标标记、战斗反馈的 renderOrder、材质边界、深度策略、活动对象上限和后处理预算。
- 背景层固定为星场/空间尘埃/远景行星 `-30/-20/-10`，范围网格 `-2`，小行星 `10`，目标标记 `30`，战斗反馈 `40`；背景、标记和反馈明确 `depthWrite=false`，标记/反馈额外关闭 `depthTest`。
- 小行星最多 10 个，采用低饱和低多边形 PBR 表面；目标标记不超过 3 个 draw call；战斗反馈共享 256 对象池，高特效活动上限 96、低特效活动上限 48；额外后处理 pass 为 0。
- 权威工作区验证通过 `npm test`（6 files / 20 tests）、`npm run typecheck`、`npm run build`；主包 649.45 kB、gzip 168.60 kB，GLTFLoader 异步 chunk 44.21 kB。
- 开发预览固定 seed `20260810`：桌面高特效约 119 FPS / 195 draw calls，低特效约 180 draw calls、render 2.93 ms 且控制台为空；390×844 低特效无横向溢出，约 96 draw calls、render 1.99 ms；200 单位保持 `VISIBLE / DETAIL = 200 / 0`、约 114 FPS、34 draw calls、render 7.36 ms，控制台为空。
- 目视结论：背景亮度、星尘密度和小行星粗糙度形成清晰但克制的纵深；目标标记不被网格/舰体遮挡；低特效仍保留轮廓、推进核心和武器轨迹，无需增加额外后处理通道。
- 视觉证据：[桌面高特效](assets/p8-round4-environment-formal-1280x720.jpg)、[桌面低特效](assets/p8-round4-environment-low-1280x720.jpg)、[390×844 低特效](assets/p8-round4-environment-low-mobile-390x844.jpg)。

### P8 声音设计事件接口

- 新增 `src/audio/audio-events.ts` 与 `src/audio/audio-events.test.ts`：事件包含 schema、eventId、cue、simulation time、声道、优先级、强度、空间位置和最小化单位引用；事件总线提供订阅、有限 QA 历史和安全强度归一化。
- 主循环已接入 `encounter-start`、`weapon-fire`、`weapon-hit`、`incoming-fire`、`unit-destroyed`、`victory`、`defeat`，以及选取、目标锁定、移动/攻击/停止、暂停/恢复、高低特效切换和错误提示等 UI cue。
- `window` 事件名固定为 `rts-audio-event`；当前只桥接事件、不播放声音。`data-audio-event-count` / `data-audio-last-cue` 仅用于开发预览 QA，不改变 simulation。
- 声音预算：combat 8 复音、warning 2 复音、ui 4 复音，单帧最多 8 个事件，QA 历史最多 96 个；适配器超预算时按 priority 丢弃低优先级事件，不得阻塞主循环。
- 权威工作区通过 `npm test`（7 files / 23 tests）、`npm run typecheck` 和 `npm run build`；开发预览固定 seed 初始事件为 `encounter-start`，按 `P` 后为 `ui-pause`，页面进入 `PAUSED`，控制台为空。
