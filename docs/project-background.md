# 项目背景与范围

## 1. 项目缘起

本项目源自一段希望“构建家园风格宇宙规模 RTS”的实验性 prompt。原始设想包含：宏大的宇宙尺度、多个舰船类型、随机模式、流畅控制、优秀 UI/HUD、着色器与生成纹理、实例化渲染，以及持续的视觉检查。

这里把它当作产品愿景和探索方向，而不是“无需验证即可达到 AAA”的承诺。项目第一阶段的目标是建立一个能够持续迭代、可测量、可优化的 3D RTS 原型，并逐步接近目标体验。

## 2. 核心体验

- 在具有深度、层次和尺度感的 3D 太空战场中观察舰队。
- 以随机模式快速生成一局可玩的遭遇，不依赖任务链和剧情内容。
- 通过编队、选中、移动、攻击、巡航和编组等操作管理多种舰船。
- 让战场信息通过清晰的 HUD、选中框、队列、状态条和小地图表达出来。
- 在舰队数量增加时仍保持稳定帧率，并为后续大规模单位数量留出技术空间。

## 3. 第一阶段范围

### 必须具备

1. 3D 太空场景、相机控制、星空/背景层和可辨识的战场坐标。
2. 至少三类舰船：侦察/轻型、战斗/中型、主力/重型；每类具备不同速度、生命值、火力或射程。
3. 随机地图或随机遭遇配置；本阶段不实现任务系统。
4. 鼠标和键盘控制：框选、单击选择、右键移动/攻击、相机平移/缩放/旋转，以及暂停。
5. 基础 UI/HUD：资源或状态区、单位信息、选中反馈、目标指示、快捷键提示和小地图占位。
6. 可复现的开发启动、构建和检查流程。

### 暂不承诺

- 不承诺一次生成“绝对完美”或直接等同商业 AAA 游戏。
- 不复制 Homeworld 的专有模型、纹理、音频、UI 或其他受版权保护资产。
- 不把“分派子代理”“/loop”当作质量保证本身；质量由可重复的验收标准、性能指标和人工/自动视觉检查共同决定。
- 本阶段不包含联机、战役、外交、完整经济系统、语音、多人同步或完整内容生产管线。

## 4. 质量基线

质量按可验证的层级推进：

1. **可玩**：操作闭环成立，单位能生成、选择、移动、攻击和销毁。
2. **可读**：不同舰船在远近视角、颜色、轮廓和 HUD 中都能区分。
3. **有尺度感**：镜头、相对速度、编队和背景层共同传达舰队规模。
4. **有表现力**：材质、灯光、推进焰、武器轨迹、爆炸和后处理形成统一风格。
5. **可扩展**：批量渲染、实例化、LOD、对象复用和空间查询支持更多单位。
6. **可交付**：每个阶段都有启动、构建、性能检查和视觉回归记录。

## 5. 初步技术方向

- 核心战场使用 Three.js，优先选择现代 GPU 管线可逐步增强的实现。
- 舰船和特效采用程序化材质、贴图/噪声、粒子与实例化；在性能数据支持后再增加几何与后处理复杂度。
- UI/HUD 先采用 DOM/CSS 与 Canvas 叠加，以便快速迭代信息层；需要大量 2D 精灵时再评估引入 PixiJS 的局部模块。
- 游戏逻辑与渲染解耦：单位数据、选择/编队、战斗计算、相机和渲染表现分别保持清晰边界。

## 6. 后续里程碑

| 阶段 | 结果 |
| --- | --- |
| M0 | 文档、仓库与开发/发布链路建立 |
| M1 | 单舰船在 3D 太空场景中可控制 |
| M2 | 三类舰船、选择/移动/攻击闭环 |
| M3 | 随机模式、编队、基础 HUD 与小地图 |
| M4 | 着色器、特效、实例化/LOD 与性能基线 |
| M5 | 视觉回归、可玩性打磨和生产发布候选版 |
